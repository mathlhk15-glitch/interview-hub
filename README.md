# 2027 대입 면접 준비 허브 — v5.1 AI-first Clean

## v5.1 핵심 변경

이번 버전은 사용자 화면에서 **로컬 규칙 기반 면접문항 생성 흐름을 완전히 폐기**하고 AI 전체분석을 유일한 기본 분석 경로로 정리했습니다.

- PDF 첨부 → 텍스트 추출 → AI 전체분석 프롬프트 → AI 결과 가져오기 → 활동별 전체 질문/A·B·C → TOP3 심화 → 말하기 연습
- 예전 `#/analysis-results`, `#/activities`, `#/questions`, `#/followups` 주소로 접속해도 새 AI 결과/학생 홈으로 자동 전환
- 예전 `#/record-map` 주소도 AI 전체분석으로 자동 전환
- 학생 홈에서 `로컬 간단 분석`, 로컬 TOP3, 로컬 자동질문 진입 버튼 제거
- PDF 글자 추출이 어색하면 AI 프롬프트 생성 과정의 **원문 확인·개인정보 제거** 화면에서 바로 수정
- D-Day·블라인드·빈출12유형·면접유형 확인은 분석 이후의 선택 보조도구로만 유지

> 기본 원칙: **프로그램은 학생부를 안전하게 AI에 전달하고, 의미 해석과 면접문항 생성은 AI가 담당합니다.**


## 핵심 방향

이 버전부터 **AI 분석이 주 기능**입니다.

프로그램 자체의 규칙 기반 질문 생성은 PDF 표 구조·줄 순서에 따라 문장이 잘릴 수 있어 기본 흐름에서 제외했습니다. 로컬 프로그램은 생활기록부 PDF를 브라우저에서 읽고, 사용자가 개인정보를 확인한 뒤 원하는 AI에 붙여넣을 **정교한 분석 프롬프트를 생성**하는 역할을 맡습니다.

기본 흐름은 다음과 같습니다.

1. 생활기록부 PDF 선택
2. 브라우저에서 전체 텍스트 추출
3. 개인정보 확인·수정
4. `생활기록부 전체 면접문항 AI 분석` 프롬프트 복사
5. ChatGPT / Claude / Gemini 등 사용자가 원하는 AI에 붙여넣기
6. AI 결과를 다시 앱에 붙여넣기
7. 전체 활동 인벤토리와 활동별 질문 확인
8. A급 필수질문부터 30·60초 말하기 연습
9. 핵심활동 TOP3는 별도 심화분석

## v5.0에서 달라진 점

### 1. AI 전체분석이 기본

이전 버전은 로컬 규칙으로 먼저 핵심활동과 질문을 만들고 AI는 심화도구로 사용했습니다.

v5.0은 반대로 설계했습니다.

- 프로그램: PDF 텍스트 추출·개인정보 확인·프롬프트 생성
- AI: 전체 활동 탐색·질문 생성·우선순위·심화분석
- 학생: 결과 확인·사실 검증·말하기 연습

### 2. 핵심활동 TOP3를 먼저 고르지 않음

AI에게 다음 순서를 강제합니다.

`전체 생활기록부 훑기 → 의미 있는 활동 전체 목록화 → 활동별 예상질문 → A/B/C 분류 → 핵심활동 TOP3 → 누락 점검`

활동 수를 임의로 3개, 5개, 10개로 제한하지 않도록 프롬프트에 명시했습니다.

### 3. 활동별 전체 예상질문

AI 결과 JSON에 `activityInventory`를 새로 추가했습니다.

각 활동에는 다음 정보가 들어갑니다.

- 활동명
- 학생부 영역/학년/과목
- 근거 원문
- 활동 요약
- 학업/진로/공동체 등 태그
- A/B/C 중요도
- 활동별 예상질문 2~4개
- 활동별 꼬리질문 1~3개

결과 화면에서는 A 활동은 펼쳐서 보여주고 B/C는 필요할 때 열어볼 수 있습니다.

### 4. 누락 점검

AI 결과의 `coverageCheck`를 표시합니다.

- 발견한 의미 있는 활동 수
- 실제 분석한 활동 수
- 활동에서 제외한 항목과 이유
- 누락 점검 메모

AI가 스스로 원문을 다시 훑어 빠진 활동이 없는지 확인하도록 프롬프트에 요구합니다.

### 5. 핵심활동 심화는 두 번째 단계

전체 분석이 끝난 다음에만 `핵심활동 TOP3 더 깊게 분석하기`를 사용합니다.

심화분석은 다음 방향으로 질문을 깊게 만듭니다.

- 사실·역할
- 동기·판단
- 개념·방법
- 과정
- 한계·보완
- 전공·진로 연결

### 6. 로컬 자동질문 사용자 흐름 폐기

기존 로컬 규칙 기반 `analysis-results`, 로컬 TOP3, 로컬 자동질문 화면은 사용자 흐름에서 제거했습니다. 예전 해시 주소로 들어와도 AI 결과 화면 또는 학생 홈으로 자동 전환됩니다.

## 무료 운영 방식

이 웹앱은 AI API를 호출하지 않습니다.

- OpenAI API 없음
- Claude API 없음
- Gemini API 없음
- API Key 없음
- 백엔드 서버 없음
- GitHub Pages에서 정적 배포 가능

사용자가 앱에서 생성된 프롬프트를 복사하여 자신이 사용하는 AI 서비스에 직접 붙여넣습니다.

## 개인정보

생활기록부 PDF는 기본적으로 현재 브라우저에서만 읽습니다.

AI를 사용할 경우에는 사용자가 **AI에 보낼 텍스트를 직접 확인한 뒤 복사**합니다. 외부 AI 서비스에 붙여넣는 순간 해당 내용은 그 서비스로 전송되므로 이름·학교명·학번·연락처 등 불필요한 개인정보를 제거한 뒤 사용해야 합니다.

앱은 생활기록부 원문을 localStorage에 자동 저장하지 않습니다.

## 알려진 한계

1. PDF.js 텍스트 추출은 NEIS PDF의 복잡한 표 구조에서 일부 줄 순서를 완벽히 보존하지 못할 수 있습니다.
2. 이 때문에 앱 자체는 추출 텍스트를 의미적으로 해석해 질문을 만드는 일을 주 기능으로 사용하지 않습니다.
3. 외부 AI도 사실을 잘못 추론할 수 있으므로 `evidenceQuote`와 학생부 원문을 확인해야 합니다.
4. AI 서비스의 무료 사용량·컨텍스트 길이·출력 길이에 따라 매우 긴 생활기록부는 결과가 잘릴 수 있습니다. 그런 경우 학년/영역별로 나누어 분석하는 것이 좋습니다.
5. 스캔 이미지형 PDF OCR은 기본 제공하지 않습니다. 텍스트 복사·붙여넣기를 사용하세요.

## 교육 원칙

이 앱은 학생 대신 면접 답을 써주기 위한 프로그램이 아닙니다.

- 학생부에 있는 사실을 근거로 질문을 만든다.
- 학생이 자기 경험을 자기 말로 설명한다.
- 핵심활동은 깊게 준비하되, 그 전에 학생부 전체에서 질문 가능성을 점검한다.
- 30초·60초 말하기를 반복한다.
- 사실 → 과정·판단 → 근거·한계로 꼬리질문을 준비한다.
- 모범답안 암기보다 실제 경험의 구체성을 우선한다.
