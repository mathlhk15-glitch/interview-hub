# 2027 대입 면접 준비 허브

`면접 지도 가이드북(ver.260825Final)`의 교육 원칙과 학생용 활동지(A1~A10) 구조를 바탕으로 만든,
**무료 · API 없음 · 서버 없음**의 모바일 우선 정적 웹앱입니다. GitHub Pages에 그대로 올려 씁니다.

이 프로그램의 목적은 **학생 대신 답을 만들어 주는 것이 아니라, 학생이 자기 경험에서 스스로
질문과 답의 재료를 찾도록 돕는 것**입니다. 완성 모범답안을 생성하는 기능은 어디에도 없습니다.

## 0. 3차 수정 변경 이력 (최종 재검수 반영)

2차 버전 재검수에서 발견된 실제 사용 흐름·데이터 일관성 문제를 추가로 수정했습니다.

| 재검수 지적 | 3차 수정 내용 |
|---|---|
| 대학 정보부터 먼저 등록하면 학생부/직접입력 시작 버튼이 사라짐 | **기록이 0건인 동안에는 대학 등록 여부와 관계없이** [학생부 PDF 불러오기]와 [학생부 없이 시작하기]를 계속 표시합니다. |
| 복수 대학 등록 시 어느 대학을 현재 준비하는지 불명확 | 학생 대시보드에 **현재 준비 대학 선택기**를 추가하고, 모든 13개 준비 STEP 화면 상단에 현재 준비 대학 배너를 표시합니다. |
| 사용자가 직접 확정한 면접유형이 AI 프롬프트 등 일부 기능에 반영되지 않음 | `effectiveInterviewType()`으로 통일해 **사용자 확정값 > 자동 추정값** 순으로 대학 카드·AI 프롬프트·특수면접 화면 등에 반영합니다. |
| 자동 태그가 빈 배열 때문에 실제로 실행되지 않음 | `tagsInitialized`를 추가해 기록 생성 후 **최초 1회 규칙 기반 추천 태그**가 적용되고, 이후 학생이 지운 태그가 다시 살아나지 않게 했습니다. |
| '실험 결과'의 '결과'가 출결로 오분류됨 | 출결 규칙에서 일반 단어 `결과`를 제거하고 결석·지각·조퇴·미인정·출결 등 명확한 표현만 사용합니다. |
| JSON 백업이 질문/활동의 `recordId`를 완전히 복원하지 못함 | 백업 포맷을 **schemaVersion 3**으로 올리고 직접입력 기록, 지원동기 상세, 모의면접 평가, 현재 준비 대학 등을 포함합니다. 학생부 파생 기록은 별도 체크 시에만 포함하며, 제외된 기록을 가리키는 `recordId`는 자동으로 끊습니다. |
| AI 답변 피드백이 일반 분석 파서로 들어가 피드백 문장까지 질문으로 저장될 수 있음 | 피드백 전용 JSON(`goodPoint`, `improvements`, `followUpQuestions`)과 전용 결과 화면을 추가했습니다. **꼬리질문만** 사용자가 선택해 질문은행에 추가할 수 있습니다. |
| AI가 요약·추정한 사실이 학생부 근거처럼 승격될 수 있음 | 핵심기록·핵심활동·설명필요 기록은 **'학생부 원문 또는 실제 경험에서 사실임을 확인'** 체크 전에는 채택할 수 없습니다. |
| 말하기 훈련 질문을 바꿔도 횟수가 누적되고 중복 실행 가능 | 질문별 시도 횟수를 따로 관리하고, 훈련 중 시작·랜덤·프레임 버튼을 잠급니다. 취소 시 타이머 Promise도 종료하고 마이크 스트림을 정리합니다. |
| 블라인드 검사에서 '○○시'→'시' 식 처리로 오탐이 큼 | 단일 글자 `시/동` 탐지를 폐기하고 학교명·등급·백분위·학원/기관·실명 형태의 **명시적 정규식**만 검사합니다. |
| 과거 면접이 '가장 가까운 면접'으로 잡힐 수 있음 | 미래/오늘 일정을 우선하고, 미래 일정이 없을 때만 가장 최근 과거 일정을 보여줍니다. |
| 기록 삭제·수정 후 연결 질문/활동이 고아 데이터가 됨 | 기록 삭제 시 연결 질문·활동 수를 안내하고 함께 삭제합니다. 기록 문장/영역 수정 시 연결 질문의 근거도 동기화합니다. |
| 설명 필요 요약이 오래된 값으로 인쇄될 수 있음 | 인쇄 시 `weaknessEntries`에서 실시간으로 요약을 다시 만들어 사용합니다. |
| 학교 공유용 익명 후기에 자유서술 개인정보가 남을 수 있음 | 익명 내보내기 직전 개인정보 후보를 경고하고 전화번호·이메일·학교명·생년월일 패턴은 자동 가림 처리합니다. |
| MMI/제시문 훈련이 너무 얕음 | MMI에는 **상황 핵심→판단→근거/상대 관점→방 이동 리셋**, 제시문에는 **비교→적용→확장** 메모 3단계를 추가했습니다. |
| 상단 진행률 막대가 0% 고정 | 현재 STEP에 따라 13단계 진행률을 자동 표시합니다. |

> 이 버전도 생활기록부 PDF의 완벽한 NEIS 표 구조 복원이나 스캔 OCR을 약속하지 않습니다. 자동 추출 결과는 학생이 확인·수정하는 것을 전제로 합니다.

## 1. 설치 없이 바로 쓰기 (GitHub Pages 배포)

1. 이 폴더 전체를 GitHub 저장소에 올립니다(루트 또는 `/docs` 폴더).
2. 저장소 **Settings → Pages**에서 배포 브랜치/폴더를 지정합니다.
3. 발급된 주소(`https://사용자명.github.io/저장소명/`)로 접속하면 끝입니다. 별도 서버, 빌드,
   `npm install` 과정이 없습니다. `index.html`을 더블클릭해 로컬에서 열어도 대부분 기능이
   동작합니다(파일 업로드 등 일부는 `file://`보다 `http://localhost`에서 더 안정적입니다.
   `python3 -m http.server`로 간단히 로컬 서버를 띄울 수 있습니다).

## 5. 생활기록부 처리 방법

- **텍스트형 PDF**: 브라우저 안에서 PDF.js(로컬 동봉 파일)로 텍스트만 추출합니다. 서버로 전송되지 않습니다.
- **표가 깨지거나 추출이 잘 안 되는 경우**: NEIS 화면에서 복사한 텍스트를 붙여넣고, 영역(세특·창체 등)을
  직접 선택하는 수동 입력 경로로 즉시 전환됩니다.
- **스캔/이미지형 PDF**: OCR을 시도하지 않고 "이미지형 PDF로 보입니다" 안내 후 직접 입력으로 전환합니다
  (아래 "구현하지 않은 기능" 참고).
- **생활기록부 없이 시작**: 언제든 가능하며, 질문 생성·활동 카드·말하기 훈련 등 핵심 기능을 동일하게 씁니다.

## 6. 개인정보 보호

- 생활기록부 파일은 **서버에 저장하지 않습니다.** 브라우저 메모리에서만 처리되고, 새로고침·탭 종료·
  [PDF 원문 버퍼만 삭제]/[학생부 관련 항목 전체 삭제] 버튼 클릭 시 사라집니다. 두 버튼은 서로
  다릅니다 — 전자는 원문 텍스트만, 후자는 학생부에서 만든 기록·활동·질문까지 모두 지웁니다.
- `localStorage`에는 테마·마지막 화면·튜토리얼 완료 여부처럼 **민감하지 않은 설정만** 저장합니다.
  대학 정보·활동·질문·후기 같은 준비 데이터는 사용자가 [JSON 내보내기]를 눌러야만 파일로 남습니다.
- JSON 백업은 **schemaVersion 3**입니다. 생활기록부 없이 직접 입력한 기록은 작업 복원을 위해 기본 포함됩니다.
  학생부에서 파생된 정리 기록은 **기본 제외**이며 별도 체크해야 포함됩니다. 질문에 딸린 "학생부 근거 문장"
  (`evidenceText`)도 기본 제외입니다. 학생부 PDF 전체 원문·녹음·AI 결과 원문은 어떤 옵션에서도 포함되지 않습니다.
- AI를 쓸 때는 학생이 보낼 내용을 직접 선택하고(성적·출결 등은 기본 체크 해제), 개인정보 제거 후보를
  확인한 뒤, 실제 전송될 내용을 미리보기로 본 다음, [확인했습니다]를 눌러야 복사 버튼이 활성화됩니다.
  ①전체분석 ②선택기록집중분석 ③답변피드백 세 모드 모두 이 절차를 동일하게 거칩니다.
- AI 분석 결과 원문과 녹음은 JSON 내보내기 대상에서 항상 제외됩니다.
- Google Analytics 등 외부 추적 코드를 쓰지 않습니다.

## 7. AI를 API 없이 쓰는 이유와 사용법

이 앱은 OpenAI/Claude/Gemini 등 어떤 유료 API도 호출하지 않습니다(운영비 0원 유지).
대신 [AI 면접 코치 활용하기]에서:
1. 보낼 내용 선택 → 2. 개인정보 확인 → 3. 전송 내용 미리보기 → 4. 프롬프트 생성 → 5. 복사
를 거쳐 텍스트를 만들고, 학생이 평소 쓰는 AI에 직접 붙여넣습니다. 결과를 복사해 앱에 다시
붙여넣으면 JSON 코드블록을 우선 인식하고, 실패하면 줄 단위 "텍스트 카드"로 자동 변환합니다
(완전 실패로 끝나지 않습니다). 모든 AI 제안 항목에는 "AI 제안" 출처 배지가 붙고, 학생이
채택/수정/삭제해야 실제 준비 데이터에 반영됩니다. 특히 AI가 제안한 핵심기록·핵심활동·설명필요 항목은
학생이 "학생부 원문 또는 내 실제 경험에서 사실임을 확인했습니다"를 체크해야만 채택할 수 있습니다.
답변 피드백은 별도 JSON 형식으로 처리하고, 꼬리질문만 선택적으로 질문은행에 추가합니다.

## 9. 알려진 한계 / 구현하지 않은 기능과 이유

지시문 원안은 PDF 추출·OCR·규칙엔진·AI 왕복·녹음·인쇄·데이터 이식·후기 제출까지 요구하는
매우 큰 범위였습니다. 안정성을 위해 **핵심 필수 기능을 완성도 있게** 만들고, 아래 항목은
의도적으로 단순화하거나 제외했습니다.

| 항목 | 상태 | 이유 |
|---|---|---|
| 브라우저 내 OCR(스캔 PDF) | 미구현 | Tesseract 등 OCR 라이브러리는 용량이 크고 저사양 모바일에서 느려지거나 멎을 위험이 큽니다. "가짜 버튼을 만들지 않는다"는 원칙에 따라, 버튼을 넣는 대신 스캔 PDF 감지 후 직접 입력·붙여넣기로 즉시 안내합니다. |
| 카메라 녹화(영상) | 미구현, 오디오 녹음만 제공 | MediaRecorder의 오디오 녹음만으로도 말버릇·속도 교정의 핵심 기능은 충족됩니다. 영상 녹화는 권한·용량·브라우저 편차가 훨씬 커 "별도 휴대전화로 녹화"를 권장 문구로 안내합니다. |
| 무거운 모듈의 지연 로딩(코드 스플리팅) | 부분 적용 | 이 버전은 빌드 도구 없는 단일 스크립트 구조를 우선했습니다. PDF.js는 `<script>` 태그로 정적 로드되며 첫 화면 렌더링을 막지 않습니다. 트래픽이 큰 학교라면 `defer` 속성 추가나 동적 `import()` 전환을 권장합니다. |
| 자동화된 브라우저 호환성 테스트(E2E) | 미구현, 수동 체크리스트로 대체 | 정적 배포 환경 특성상 별도 CI 없이 아래 "테스트 결과"의 수동 시나리오로 검증했습니다. 최소 지원 대상: 최신 Chrome(Android/데스크톱), Safari(iOS), Edge. iOS Safari는 오디오 MIME이 제한적이라 `trainer.js`가 자동으로 지원 코덱을 탐색하고, 실패 시 스톱워치 모드로 전환합니다. |
| 대학별 실제 기출문항 데이터베이스 | 의도적 제외 | 이 앱은 어떤 기출도 임의로 만들어내지 않습니다. 실제 기출은 학생이 선행학습 영향평가 결과보고서 등에서 직접 찾아 [내가 찾은 기출 붙여넣기]에 입력하도록 설계했습니다. |
